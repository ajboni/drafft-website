API Documentation

Drafft includes an optional local REST API for reading a loaded project. It is designed for integrations, tooling, and agents that need document-level access without clicking through the app.

tip

The API only works while Drafft is running and a project is loaded. The server listens on 127.0.0.1 only.

App Options​

  • Enable API: Starts the local REST API when a project is opened.
  • API Key: Required for read requests. Send it as x-api-key, or as Authorization: Bearer <key>.
  • API Port: The local port to listen on. Default 9001.
  • Enable Write API (preview): Enables write-capable endpoints.
  • Write API Key: Required for write requests. A read key cannot write.

Base URL:

http://127.0.0.1:9001

Discovery​

These endpoints do not require a key.

GET /
GET /v1/health
GET /v1/openapi.json

GET / returns the app version, API version, and whether the write API is enabled. GET /v1/openapi.json returns the full OpenAPI description.

Readiness​

GET /v1/ready

Returns the current readiness flags:

{
  "ready": true,
  "dbLoaded": true,
  "variablesReady": true,
  "searchReady": true,
  "writesEnabled": false,
  "writesReady": false
}

searchReady is false while the search index is being built. GET /v1/search returns 425 until it is ready.

Project info​

GET /v1/info

Returns the project name/version/description, app version, current user, capabilities, and readiness.

Documents​

Get one document​

GET /v1/documents/:id

Returns the raw database document, including _rev. Optional query parameters:

  • fields - comma-separated top-level fields to return, for example _id,name,type,collection,parent,path.
  • include - content, revs, or attachments.
GET /v1/documents/abc123?fields=_id,name,type,collection,parent,path

Bulk fetch​

GET /v1/documents?ids=id1,id2,id3

Returns { items, missing }. Maximum 100 ids per request.

List collections​

GET /v1/collections
GET /v1/collections?includeInternal=true

Returns collection names with total and per-type counts:

{
  "items": [
    { "collection": "Dialogue", "total": 12, "types": { "Dialogue": 10, "Folder": 2 } }
  ]
}

Internal collections such as User are excluded by default. Pass includeInternal=true to include them.

List documents in a collection​

GET /v1/collections/:name/documents?limit=50&offset=0&type=Dialogue&parent=<folderId>&q=aria
  • limit - 1 to 500, default 50.
  • offset - zero-based result offset, default 0.
  • type - filter by document type.
  • parent - filter by parent document id.
  • q - case-insensitive name/alias filter.
  • fields - field projection. Lists return a summary by default.
  • include=content (or fields=*) - return full documents, including content.

Returns { items, offset, limit, count, nextOffset, hasMore }. Use nextOffset for the next page while hasMore is true.

The default summary fields are _id, name, type, collection, parent, path, modified, locked, lockedBy, and alias. This keeps list responses small and usable in an LLM context; request include=content only when you need the document body.

Date fields in v1 read responses are normalized to ISO 8601. Bundles and exports keep the stored values.

Use the collection values returned by GET /v1/collections (for example Dialogue, Script, Actor). These are the database collection names, not the plural export-section names used by /game-export.

Folder children and ancestors​

GET /v1/documents/:id/children
GET /v1/documents/:id/ancestors

children returns direct children for a folder. ancestors returns the parent chain, root first.

Document state probe​

GET /v1/documents/:id/state

Reports the state a client needs before writing:

{
  "id": "abc123",
  "exists": true,
  "collection": "Dialogue",
  "type": "Dialogue",
  "rev": "3-...",
  "locked": false,
  "lockedBy": null,
  "lockOwnerType": null,
  "tabOpen": true,
  "tabKind": "main",
  "wasModified": false,
  "hasSemanticEdits": false,
  "dirtyKind": null,
  "selected": true,
  "ready": true
}

wasModified is the raw buffer diff. hasSemanticEdits ignores runtime-only layout fields (measured, dragging, selected) and reflects authored changes. dirtyKind is "user", "normalization", or null.

If the document does not exist, the endpoint returns exists: false rather than an error.

Revisions​

GET /v1/documents/:id/revisions

Returns the revision id and the available revision list.

Dialogue nodes​

GET /v1/documents/:id/nodes
GET /v1/documents/:id/nodes?include=script

Lists the nodes of a dialogue:

{
  "items": [
    {
      "id": "node123",
      "label": "Enter the garden",
      "nodeType": "script",
      "scriptId": "script123",
      "position": { "x": 20, "y": 270 },
      "route": "/dialogue/dialogue123/node/node123/script/script123",
      "script": {
        "id": "script123",
        "name": "Enter the garden",
        "editorMode": "text",
        "content": { "script": "::Narrator:: The garden is quiet..." }
      }
    }
  ]
}

With include=script, each node includes its script document, so you can read a dialogue and its lines in one call. Without it, the response only contains scriptId.

Returns 400 not_a_dialogue for non-dialogue documents. Use the route to open the dialogue focused on that node.

References​

GET /v1/documents/:id/references?direction=incoming|outgoing|both

Returns structural links to and from a document. This is computed on demand from the current project data; there is no secondary index to get out of sync.

{
  "incoming": [
    {
      "direction": "incoming",
      "kind": "dialogue-node-script",
      "confidence": "structural",
      "docId": "dialogue123",
      "docName": "3 - Memory Exploration",
      "nodeId": "node123",
      "nodeLabel": "Destiny unfolds",
      "route": "/dialogue/dialogue123/node/node123/script/script123"
    }
  ],
  "outgoing": [
    {
      "direction": "outgoing",
      "kind": "dialogue-script-folder",
      "confidence": "structural",
      "docId": "folder123",
      "docName": "3 - Memory Exploration",
      "route": "/folder/folder123"
    }
  ]
}

Currently covered:

  • dialogue → script folder, node scripts, related docs
  • script → parent folder, owning dialogue
  • scene → playlist items
  • GDD → :doc{#id} links
  • incoming: dialogue node → script, scene → dialogue/script, GDD → document, related docs

Textual mentions (variable/actor names inside scripts) are not included yet.

Bundles​

A bundle is a partial project export in the same { rows } shape used by project backups. It can be imported into another project.

GET /v1/documents/:id/bundle
GET /v1/documents/:id/bundle?dependencies=true

With dependencies=true, a Dialogue bundle also includes its script folder and node scripts.

GET /v1/documents/export?ids=id1,id2
GET /v1/documents/export?collection=Dialogue

Use either ids or collection, not both. Exported documents omit internal fields such as _rev, locked, and lockedBy. Dialogue bundles also omit runtime layout fields (measured, dragging, selected) so they are portable across machines and app versions.

Search​

GET /v1/search?q=aria&scope=documents&collection=Actor&type=Actor&limit=20&offset=0
GET /v1/search?q=garden&scope=nodes
GET /v1/search?q=garden&scope=all

scope is documents (default), nodes, or all. Document results have kind: "document"; dialogue node results have kind: "node" and their own score and snippet. Node results use collection: "Dialogue" and type: "DialogueNode", so type=Dialogue filters documents only and type=DialogueNode filters nodes.

Document result:

{
  "kind": "document",
  "id": "abc123",
  "name": "Aria",
  "collection": "Actor",
  "type": "Actor",
  "path": "Characters.Aria",
  "score": 12.4,
  "snippet": "..."
}

Dialogue document results also include matching nodes and a focus target:

{
  "kind": "document",
  "id": "dialogue123",
  "name": "1 - Opening Scene",
  "collection": "Dialogue",
  "type": "Dialogue",
  "nodeMatches": [
    { "id": "node123", "label": "Enter the garden", "scriptId": "script123" }
  ],
  "focus": {
    "nodeId": "node123",
    "label": "Enter the garden",
    "scriptId": "script123",
    "route": "/dialogue/dialogue123/node/node123/script/script123"
  }
}

Node result (scope=nodes or scope=all):

{
  "kind": "node",
  "id": "node123",
  "dialogueId": "dialogue123",
  "dialogueName": "1 - Opening Scene",
  "nodeId": "node123",
  "label": "Enter the garden",
  "nodeType": "script",
  "scriptId": "script123",
  "route": "/dialogue/dialogue123/node/node123/script/script123",
  "score": 9.8,
  "snippet": "...",
  "collection": "Dialogue",
  "type": "DialogueNode"
}

The query must be at least 2 characters. limit is capped at 100. Node search ignores common stopwords (the, a, of, etc.) so a query does not focus an unrelated node.

Errors​

All v1 endpoints return errors in the same shape:

{
  "error": {
    "code": "not_found",
    "message": "Document not found: abc123",
    "reason": null,
    "details": null
  }
}

Common status codes:

StatusMeaning
400Malformed request or missing parameter
401Missing or invalid read key
403Write API disabled or write key required
404Document or route not found
409Conflict (reserved for write operations)
423Locked (reserved for write operations)
425Project or search index not ready
500Unexpected server error

Legacy endpoints​

These endpoints remain available for existing integrations.

Get project info and settings​

GET /info

Get game export​

Gets a game-ready JSON object. Same as clicking "Export Game Content" in the app.

GET /game-export

The exported collections come from the project settings, and can be filtered with a comma-separated collections parameter:

  • ProjectSettings, GDD, Scripts, Dialogues, Actors, Quests, Items, Variables, Scenarios, Scenes, Misc, Grids, Kanban, Canvas, Maps
GET /game-export?collections=Scripts,Dialogues,Variables,Scenarios

Get JSON Schema export​

GET /schema-export
GET /schema-export?collections=Scripts,Dialogues

Get database dump​

Gets a raw PouchDB dump. This is a backup endpoint, not a normal read endpoint. It accepts PouchDB allDocs options; defaults are include_docs: true and attachments: true.

GET /db-dump
GET /db-dump?include_docs=false&attachments=false

Navigate to a document​

Opens a document in the app.

GET /navigate?id=DOCUMENT_ID

To focus a specific dialogue node, add nodeId (and optionally scriptId):

GET /navigate?id=DIALOGUE_ID&nodeId=NODE_ID
GET /navigate?id=DIALOGUE_ID&nodeId=NODE_ID&scriptId=SCRIPT_ID

The response includes the resolved route. The app opens the dialogue, centers the node, and opens its script subtab when a script is available.
