# Scenarios

## Overview

Scenarios store simulation state as diffs. They are ideal for testing narrative branches and reproducing specific game states.

:::important
A Scenario is a diff, not a full state snapshot.
:::

## Core Behavior

- Loading a Scenario creates a snapshot baseline for divergence tracking
- Live state is populated from the Scenario diff
- Authored defaults remain unchanged
- Divergence is tracked by comparing Live state to the loaded Scenario snapshot

## Benefits

- Smaller scenario files
- Clear intent (only changed values are stored)
- Reliable branch testing without mutating authored defaults

## Typical Workflow

1. Author Variables defaults
2. Load or create a Scenario
3. Simulate scripts/dialogues and modify state
4. Save as new Scenario, or update the source Scenario after review

See [State & Simulation Lifecycle](/docs/reference/state-and-simulation-lifecycle) for lifecycle details.

## Export Behavior

When included in game export, Scenario content is exported as parsed JSON diff data.


## Collection Overrides

Scenarios can now override authored Quest, Item, and Actor values in addition to Variables. Stored scenario content uses a collection-keyed shape:

```json
{
  "collections": {
    "Variable": { "raw": "player: { gold: 250 }", "json": "{\"player\":{\"gold\":250}}" },
    "Quest": { "raw": "questA: { status: \"complete\" }", "json": "{\"questA\":{\"status\":\"complete\"}}" }
  },
  "collectionsVersion": 2
}
```

The legacy `scenario` and `json` fields remain as a Variable-only mirror for older clients. Existing scenarios are mapped in memory when opened and are written in the new shape on their next save.

In the app, a scenario opens in a read-only overview that lists every collection's overrides at once. Use the Variables, Quests, Items, and Actors tabs to edit values.

`@set q.questA.status = "complete"` creates an override that appears here. Loading the scenario reapplies it. Quest/Item/Actor overrides for unknown `_sid`s are ignored with a warning; Variable overrides remain dynamic.

When exported, scenarios keep the legacy flat Variable diff at `content` and expose other collection diffs under `content.$collections`.
