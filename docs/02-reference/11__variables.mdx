# Variables

## Overview

Variables are the authored default state for your project. Scripts and dialogue logic can read and update variable values during simulation.

## What Variables Are Used For

- Tracking player state (`mood`, `health`, `trust`, flags)
- Driving branching dialogue and conditions
- Interpolating values in script text via `${variables...}`
- Defining a clean baseline for Scenarios

## Authoring Model

- Variables are authored as document content
- Defaults are stable project data
- Simulation writes happen against Live state, not authored defaults

See [State & Simulation Lifecycle](/docs/reference/state-and-simulation-lifecycle) for the deeper mental model.

## Variable Documents Are Sets

A Variable document is a **variable set**, not a single scalar value. The document is the container; its fields become properties under the root variable name.

The root name comes from `content.json._sid`. The document name and document id are labels and may differ from the variable path.

Example: a document named `Player` with `_sid: player`:

```json
{
  "_sid": "player",
  "style": "A"
}
```

is read in scripts as:

```uaf
variables.player.style
```

The matching HJSON editor content is:

```hjson
_sid: player
style: A
```

`content.variables` (HJSON) and `content.json` (JSON) describe the same set and should agree. Keep the `_sid` stable once scripts reference it.

To change the value:

```uaf
@set variables.player.style = "B"
```

To branch:

```uaf
@if variables.player.style == "A"
::Aries:: ...
@endif
```

Do not derive the script path from the document name or document id. Always use `_sid` as the root variable name.

## Shared Structured Document Model

Variables are the mutable runtime namespace. Quest, Item, and Actor documents use the same parser/validator and canonical JSON pattern, but their authored values are read-only defaults unless a live override is created during simulation. See the scripting syntax reference for `q`, `i`, and `a` aliases.

Variables remain HJSON-authored in this version; the per-document format selector applies to Quest, Item, and Actor documents.

## Script Integration

Variables can be modified during simulation with `@set`:

```uaf
@set variables.player.mood = "curious"
::Narrator:: Current mood is ${variables.player.mood}.
```

## Export Behavior

When game export includes Variables, they are serialized as parsed JSON content.

See [Drafft Output Schema](/docs/reference/exporting/exporting_schema) for export details.
